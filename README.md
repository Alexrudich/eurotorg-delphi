# Складской учёт — тестовое задание

Простой количественно-суммовой учёт на **Delphi RAD Studio 13.1 + FMX + FireDAC + MS SQL Server Express**.

Учёт ведётся в разрезе **партий** и **мест хранения**. Все операции (приход,
перемещение, расход) оформляются документами; остатки на любую дату
восстанавливаются по журналу движений.

---

## Что реализовано

| Возможность | Где |
|---|---|
| Справочники: товары, склады, места | вкладки «Товары», «Склады», «Места» — грид + добавить/изменить/удалить. Поиск вверху вкладки + сортировка по клику на заголовок колонки. |
| Приход | вкладка «Приход» — товар, склад, место, дата/время, кол-во, цена, срок годности, комментарий |
| Расход по FIFO | вкладка «Расход» — товар, кол-во; партии подбираются по дате прихода |
| Расход вручную | там же, галочка «Вручную» + номер партии |
| Перемещение | вкладка «Перемещение» — часть партии на другое место/склад |
| Реестр документов | вкладка «Документы» — фильтр по типу и периоду |
| Остатки на дату/время | вкладка «Остатки» — хранимая процедура `usp_StockOnDate` |

Каждая операция пишет документ (`Document` + `DocumentLine`) и движения
регистра (`StockMovement`). Остаток партии — сумма движений; поле
`Batch.Quantity` — кэш для FIFO и проверки «не уйти в минус».

Перед записью расхода показывается диалог подтверждения с расчётом
(какие именно партии будут списаны). Ошибки («не хватает 8 шт») выводятся
до открытия транзакции.

## Структура

```
Source/
  Data/uDM.pas          — весь доступ к данным: соединение, транзакции, запросы
  Forms/MainForm.pas    — единственная форма, все вкладки создаются кодом
Warehouse.dpr           — точка входа, инициализация DM, обработка ошибок
Sql/
  01_schema.sql         — таблицы, индексы, ограничения, usp_StockOnDate
  02_seed.sql           — демонстрационные данные и самопроверки
  00_smoke_test.sql     — быстрые проверки после развёртывания
  03_perf_seed.sql      — генератор нагрузочных данных (WarehousePerfTest)
  04_perf_measure.sql   — замеры производительности ключевых запросов
```

## Развёртывание

### 1. База данных

Вариант А — локальный MS SQL Express:

```powershell
sqlcmd -S "localhost\SQLEXPRESS" -E -C -i Sql\01_schema.sql
sqlcmd -S "localhost\SQLEXPRESS" -E -C -i Sql\02_seed.sql
```

Вариант Б — Docker (см. `docker-compose.yml`): поднять контейнер, затем
выполнить те же два скрипта против `localhost,1433`.

Проверка:

```powershell
sqlcmd -S "localhost\SQLEXPRESS" -E -C -i Sql\00_smoke_test.sql
```

### 2. Строка подключения

Задана в `uDM.ApplyConnectionParams`:

```
Server=localhost\SQLEXPRESS
Database=WarehouseDB
OSAuthent=Yes            (Windows-аутентификация)
ODBCAdvanced=TrustServerCertificate=Yes
```

Для другой машины правится только `Server`/`Database` в одном месте.

### 3. Сборка

RAD Studio: открыть `Warehouse.dproj` (не `.groupproj`), F9.

Из командной строки:

```powershell
powershell -ExecutionPolicy Bypass -File build_fmx.ps1
```

### 4. Запуск

```bash
./run_fmx.sh          # или Warehouse.exe напрямую
```

## Тесты

### Интеграционный smoke-тест

```cmd
build.cmd
```

Собирает `smoke.dpr` и запускает `bin\smoke.exe`. 14 проверок в трёх
сценариях:

| Часть | Что проверяет |
|---|---|
| A | Отчёт «остатки на дату» на 5 контрольных точках (сид-данные) |
| B | Жизненный цикл: приход → FIFO-расход через границы партий → сверка остатков и кэша |
| C | Поиск и сортировка справочника (тот же код, что использует UI) |

Ожидаемый результат: `SMOKE OK`, exit 0.

## Генерация нагрузочных данных и замеры

```powershell
# Пересоздать базу WarehousePerfTest (700k партий, ~980k движений)
sqlcmd -S "localhost\SQLEXPRESS" -E -C -v BATCHES=700000 -i Sql\03_perf_seed.sql

# Замеры (не меняет данные, выводит STATISTICS TIME/IO)
sqlcmd -S "localhost\SQLEXPRESS" -E -C -i Sql\04_perf_measure.sql
```

Удаление нагрузочной базы: `DROP DATABASE WarehousePerfTest` (в конце
`03_perf_seed.sql`). Рабочая `WarehouseDB` не трогается.

Результаты замера на 980k движений — в `docs/PROJECT.md`, раздел 3.

## Известные ограничения

- **Однопользовательский режим.** Соединение одно, MARS не включён:
  на время транзакции курсоры справочников закрываются и затем
  восстанавливаются (`SaveAndCloseDictCursors`).
- **Редактирование строк документа не предусмотрено.** Документ создаётся
  целиком одной операцией; для исправления оформляется обратная операция.
- **Партия не пересчитывается при перемещении между складами** — создаётся
  новая партия на новом месте с той же ценой и датой прихода. Старая
  уменьшается на перемещённое количество.
- **Цена — атрибут партии**, а не товара: у одного товара в разных партиях
  цена может отличаться, и суммовой учёт это учитывает.
- **Отчёт «остатки на дату»** считает на конец выбранного дня
  (`MovementDate <= 23:59:59.999`), а не на начало.
- **Интерфейс не локализован** и рассчитан на одного оператора за рабочим
  местом; массовый ввод через таблицу не поддерживается.
